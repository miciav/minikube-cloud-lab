MongoDB — minikube-cloud-lab

1. Select your lab context and check the namespace:
   kubectl config current-context
   kubectl config view --minify -o 'jsonpath={..namespace}'
   Expect default. An empty value also means default.
   cd kubernetes/lecture02

2. In a fresh environment:
   kubectl get storageclass
   kubectl apply -f 00_es03_mongo-keyfile_secret.yml
   kubectl apply -f 02_es03_mongo_svc.yml
   kubectl apply -f 01_es03_mongo_statefulset.yml
   kubectl rollout status statefulset/mongo --timeout=180s

3. Initialize the replica set once:
   kubectl exec -i mongo-0 -- mongo --quiet < 03_es03_mongo-init.js
   Skip initialization if the replica set is already configured. Preserve existing PVCs and data.

4. Wait for the election and check the result:
   kubectl exec -it mongo-0 -- mongo
   rs.status().members.map(m => ({name:m.name, state:m.stateStr}))
   Expect one PRIMARY and two SECONDARY members. Type exit to leave.

5. Before creating other users, open a shell in the PRIMARY Pod. Replace mongo-0 with its actual name if needed. Run:
   use admin
   db.createUser({user:"labadmin", pwd:passwordPrompt(), roles:[{role:"root",db:"admin"}]})
   db.auth("labadmin", passwordPrompt())
   rs.status().members.map(m => ({name:m.name, state:m.stateStr}))
   Choose your own password and keep it out of manifests and slides. The isolated lab uses the root role for simplicity. Creating the first user closes the localhost exception. For subsequent connections use:
   kubectl exec -it mongo-0 -- mongo -u labadmin -p --authenticationDatabase admin
   Skip createUser if the user already exists.

Storage: cloud-standard, three 512Mi PVCs on NFS.
   kubectl get pvc
   kubectl get pv -o yaml
From the configured lab terminal:
   cloud volumes list
The lab uses a different provisioner from /var/hostpath-provisioner/default. Editing a manifest cannot change the StorageClass of an existing PVC. Plan a migration to preserve its data.

The mongo:4.2 image includes the mongo shell. The StatefulSet and PVCs provide identity and storage. rs.initiate configures application-level replication. The keyfile authenticates members. Clients still need user credentials.

Source: https://www.mongodb.com/docs/manual/tutorial/deploy-replica-set-with-keyfile-access-control/
